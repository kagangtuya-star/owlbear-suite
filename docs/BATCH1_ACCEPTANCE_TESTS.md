# 第一批真实房间验收手册（2026-08-21）

> 环境：dev 频道，DM + 两名玩家，明暗主题各过一遍。所有"失败路径"都必须在控制台留下带 ID 和阶段的日志——没有日志即验收失败（项目纪律）。

## 1. 状态追踪

- **快速增删**：调色板开着，右键涂抹一个状态扫过 5+ 个 token；再对单个 token 反复点选同一状态。控制台不得出现 deleteItems/addItems 报错风暴；停手后气泡无重复、无丢失。
- **多端并发**：玩家 A、B 在 1 秒内对同一 token 各切换不同状态，DM 旁观。两个状态都在（或有可解释的 last-write-wins 日志）；**只有 DM 客户端**的网络里出现气泡 addItems（玩家端必须没有——验证唯一写者门禁）。
- **切场景 + 重进**（修复前必坏路径）：上状态 → 切到别的场景 → 切回来，气泡必须重新出现。再让 DM 硬刷新页面重进：气泡重建一次、无重复。再测 DM 降权→升权。
- **替换路径**：给 10+ 个带气泡 token 的某状态在目录里改颜色——所有气泡变色、一个都不许消失。中途断网制造失败：控制台必须有 token ID + item ID + 阶段（delete/add）日志，恢复后下一次同步自愈。
- **回合数**：先攻推进一回合——带回合数的状态恰好减一，到期的气泡消失。
- **渲染模式按钮**：玩家端应看不到该按钮（GM 专属）。

## 2. 角色卡资源 ID（需先部署卡片服务器！）

- **新卡**：xlsx 特殊资源里放两个同名中文能力（如两行"狂暴"）+ 一个近似名（"狂暴击"）。绑定后用 metadata-inspector 看：每条 ID 形如 `auto-狂暴-xxxxxxxx`（同名第二条带 `-2`）。资源面板里所有行都显示；点 B 行只动 B 行；删 B 行 A 行还在。
- **旧数据修复**：用 inspector 手工造一个含两条 `auto-` ID + 一条空 ID 的 token，绑卡：控制台出现逐条 `resource-id repair` 日志 + 汇总；备份键存在；三条资源各自独立；数值不变。
- **回滚**：点"撤销 ID 修复"（有确认框）→ 仅 ID 回到旧值，数值和新增资源保留；重新绑卡 → 修复出的 ID 与第一次完全一致（确定性）。
- **重复导入**：花掉 2 个法术位 → /refresh 同一 xlsx → 重绑：仍是"剩 2"，max 更新，ID 逐字节不变。
- **预设**：把含旧 `auto-` ID 的预设对同一 token 连续应用 3 次——资源数不增长（幂等）。

## 3. 传送门

- **首次拖动**：进场景后第一把（token 未被选中过）一口气拖进传送门 → 弹目的地气泡（历史 bug 是要拖两次）。
- **启动已选中**：选中 token 后刷新客户端，直接拖 → 触发。
- **连续快拖**：拖 A 进门 → 关气泡 → 拖出 → 立刻再拖回；以及拖 A → 点 B → 再拖 A —— 每次都触发。
- **传送后**：传送完 700ms 内拖回目的门不触发（抑制窗口）；700ms 后触发。
- **切场景**：DM 切场景后新场景第一拖 → 触发（验证模块自己的 onReadyChange 重建）。
- **归因**：玩家拖自己的 token，DM 端不弹气泡；DM 拖玩家 token，DM 端弹。
- **失败日志**：目的门被删后再选它 → 控制台 error 带 entryId/destPortalId/tokenIds；用墙围死落点 → toast + 控制台带坐标明细。

## 4. 变身

- 变身后右键：玩家看不到"变身"只见"解除变身"；**DM 仍能打开选择器改授权政策**，但选怪会被拒绝（通知 + 控制台日志）。
- 双开竞态：开着选择器，另一端先变身，再选怪 → 拒绝 + `apply refused: stack non-empty` 日志；快速双击选怪 → 只产生一层栈。
- 控制台直发 `transform:apply` 广播打已变身 token → 拒绝有日志。
- 旧嵌套数据：手工造 2 层栈（含一条无 metadata 的旧格式）→ 解除两次逐层还原，最后 变身 菜单回来。
- 两种 HP 模式各变身/解除一轮，确认恢复值（注意：卡片 HP 模式解除后回快照——待拍板是否改）。
- 设置→怪物图鉴的"修复旧图片地址"仍能改写已变身 token 栈里的 URL。

## 5. displayAs

- 造一只怪：spellcasting 五条——无 displayAs / action / bonus / reaction / `displayAs:"garbage"`。三条链（怪物详情、全局搜索预览、Monster Studio 粘 JSON）里：无标记的留在"施法"，其余进对应区域**末尾**；目标区域原生条目为空时区域标题仍出现；garbage 条目留在施法且**每条链恰好一条** console.warn（带怪名+条目名+原值）。
- 详情页里被路由的块中 {@dice}/{@hit} 仍可点投，法术 chip 仍能带入搜索。
- 回归：无 displayAs 的经典怪（Lich 等）三条链渲染与 1.1.10 逐像素一致、零新增控制台输出。Studio 中英文示例都演示 bonus 路由。

## 6. 武器编辑布局

- 大卡编辑模式，中/英界面 + <600px / 600-900px / >900px 三档宽度：每个武器编辑行 `scrollWidth <= clientWidth`，删除 × 可见可点。
- 第 3（伤害）、第 4（伤害类型）输入框：点击、输入、光标落位、值经 onPatch 往返仍在；`document.elementFromPoint` 中心命中的是该输入框本身。
- 背包编辑行同测。回归：查看模式武器行、护甲/盾牌行、简介编辑字段外观不变。
